# What is ZeroDrift?

ZeroDrift is building agent-native security infrastructure for smart contract review. The current repository focuses on Move: it packages the audit methodology, specialist agent roles, validation rules, and platform-specific vulnerability references needed to review Sui and Aptos code with more consistency than a single ad hoc prompt.

The goal is simple: help reviewers and coding agents find the issues that matter, preserve the evidence chain, and turn noisy model output into structured, defensible audit findings.

## Move vulnerability detection

ZeroDrift's Move audit pack is organized around an orchestrator skill, specialist agents, and focused reference modules.

The orchestrator in `skills/move-auditor/SKILL.md` defines the audit flow:

1. Detect whether the target project is Sui or Aptos by scanning `Move.toml` dependencies.
2. Discover in-scope `.move` files while excluding tests, examples, docs, scripts, mocks, and test files.
3. Bundle source code with shared Move references and platform-specific audit modules.
4. Run specialist review passes for distinct vulnerability domains.
5. Trigger depth follow-up when a breadth finding needs token-flow, state-trace, or edge-case analysis.
6. Deduplicate, gate-evaluate, score confidence, and format the final report.

This makes the audit process repeatable: every finding should be tied back to source behavior, validation gates, and a specific vulnerability class rather than model intuition alone.

### Sui reference pack

The Sui pack currently includes 24 modules: core vulnerabilities, Sui-specific vulnerabilities, attack vectors, ability analysis, type safety, object ownership, PTB composability, package version safety, dependency audit, centralization risk, semi-trusted roles, token-flow tracing, zero-state return, flash-loan interaction, share-allocation fairness, oracle analysis, temporal parameter staleness, migration analysis, cross-chain timing, economic design audit, external precondition audit, fork ancestry, bit-shift safety, and verification protocol.

Representative Sui checks include:

- Unauthorized object transfer and shared-object manipulation.
- PTB atomic composition attacks.
- Capability leakage through `AdminCap`, `OwnerCap`, `UpgradeCap`, or permissive abilities.
- Dynamic field abuse and transfer policy bypass.
- Balance-dependent donation, dust, and share-allocation edge cases.

Representative Aptos checks include:

- Signer validation bypass and unauthorized resource access.
- FungibleAsset `Ref` lifecycle and capability misuse.
- Move 2.2+ dynamic-dispatch reentrancy risks.
- Table, SmartVector, event, and auth-key edge cases.
- Balance accounting, oracle staleness, and migration safety.

## Validation and reporting

ZeroDrift is designed to reduce false positives by requiring findings to survive a structured reporting path:

- collect source evidence before asserting impact;
- group duplicate findings by module, function, and bug class;
- promote leads only when exploitability is traced, multiple agents agree, or depth analysis confirms the issue;
- score confidence and exclude rejected items from the final report;
- keep platform-specific reasoning in the Sui or Aptos module that owns it.

The result is an audit workflow that can run inside coding agents while still matching the discipline expected from human security review: source-grounded claims, explicit assumptions, and reproducible validation steps.

## Status

This is an active ZeroDrift research and reviewer-support pack for Move security automation. It currently targets Sui and Aptos smart contracts and should be treated as workflow support for experienced reviewers, not a replacement for final human judgment.
